# research

1. **Scope**: что исследуем + зачем (связь с CORE/проектом). Определить границы темы. Если связь с CORE/project неочевидна — уточнить у пользователя
2. **Поиск** (параллельно):
   - GitHub topics/repos по теме
   - Web-поиск (статьи, доки)
   - Wiki: `context "тема" -n 3` — что уже знаем
3. **Фильтр**: оставить авторитетные/релевантные. Критерии: stars, org-коммиттер, активность, цитируемость. Отсеять нерелевантные + vaporware
4. **Углубление**: README/docs топ-3-5 источников. Извлечь архитектурные решения, паттерны, trade-offs
5. **Синтез**: таблица сравнения + gap analysis vs текущее CORE/проект. Что у нас есть, чего нет, что релевантно
6. **Результат**: markdown отчёт пользователю (не wiki-страница). Формат: таблица + выводы + приоритизированные практики
7. **Ingest решение**: если найдено ценное знание → предложить ingest (по соглашению, не автозапись). Если пользователь отказался — конец
8. **Запись в `wiki/log.md`**: `core log research "Короткая тема" --источники "топ-3-5" --находки "2-3 предложения" --ingest "да/нет"` (или вручную)
