# Balance Methodology

Практический фреймворк для построения игрового баланса от констант до экономики. Согласно [[2026-05-16-gdcuffs-balance-series]].

## Principles

1. Баланс = геймдизайн, не математика. Правильные ответы в геймплее
2. Таблички упрощают работу, но не делают лучше. Матмодель = гипотеза
3. Reverse engineering чужого баланса без опыта скорее навредит
4. Синергии не балансировать превентивно -- решать по аналитике когда проблема возникла

## Workflow

```
Константы -> Прогрессии -> Эффективность -> Экономика
```

Одни значения задаются, другие из них выводятся. Выбор зависит от того, что важно контролировать.

## Constants

Значения, заданные заранее или с потолка (логика + здравый смысл). Все остальное выводится из констант.

**Правило**: что важно = константа, что неважно = выводится.

Пример: в мобильном баттлере важна длительность боя ~1 мин = константа. Отношение HP/DMG неважно само по себе = выводится (HP = 6 * DMG при 5сек/атаку, поочередные атаки).

Неважно = можно случайно поломать в расчетах. Важно = под прямым контролем.

Не пытаться выписать все константы сразу -- они будут меняться и пополняться.

## Formula Progressions

**Формула**: `value = level^X * Y`

Подгонка X (скорость роста) и Y (масштаб) под:
- крайние значения (самый слабый vs самый сильный юнит)
- скорость роста (насколько 8-й уровень отличается от 9-го)

**Почему не рекурсивные** (Фибоначчи, арифметическая/геометрическая прогрессия):
- сложно выразить в виде формулы
- можно работать только внутри таблиц
- формула Фибоначчи сложна для модификации

### Base Progression

Одна прогрессия для важнейших значений. Производные через:
- множитель: `derived[i] = base[i] * M`
- степень: `derived[i] = base[i]^K` (другая скорость роста)

Снижает путаницу при множестве связей в игре.

### Round Values

Часто отображаемые числа (опыт до уровня) -- округлять через MROUND. Столбец проверки: текущее > предыдущего (округление может нарушить рост).

## Pre-Table Preparation

Жанр/платформа определяют порядок чисел:

| Контекст | Требование к числам |
|----------|-------------------|
| Тактические бои | Маленькие (игрок считает в уме) |
| Idle/incremental | Огромные (иллюзия быстрого роста) |
| Action с визуализацией урона | Различимые визуально (не 1, не 131348) |
| Мобильные | Учитывать размер экрана |
| RPG прокачка | Разница ощутима, рост чувствуется |
| PvP | Разрыв между близкими уровнями не слишком большой |

Быстрый рост на старте + равномерная подача контента по времени.
