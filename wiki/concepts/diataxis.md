# Diátaxis

Фреймворк структурирования документации. Классифицирует содержание по двум осям: **действие↔познание** и **приобретение↔применение навыков**. Результат — 4 вида документации с чёткими границами.

Источник: [diataxis.fr](https://diataxis.fr/)

## Карта Diátaxis

| | Приобретение навыков (study) | Применение навыков (work) |
|---|---|---|
| **Действие** | Tutorial | How-to guide |
| **Познание** | Explanation | Reference |

Ключевой инсайт: пересечение или размытие границ между видами — корень большинства проблем документации.

## Четыре вида

### Tutorial (учение → действие)

Урок: ведёт студента за руку через практический опыт. Цель — развитие навыков и уверенности, не решение задачи. Пример: «Создадим простую игру на Python». Инструктор отвечает за безопасность и успех ученика.

### How-to guide (работа → действие)

Практическое руководство для компетентного пользователя, решающего реальную задачу. Работа, а не учёба. Пример: «Как настроить профилирование фреймов», «Устранение неполадок деплоя».

### Reference (работа → познание)

Техническое описание: факты, необходимые для корректной работы. Нейтрально, не привязано к задаче пользователя. Архитектура reference отражает структуру описываемого объекта (как карта — территорию).

### Explanation (учение → познание)

Контекст и предпосылки: почему так, а не иначе. Может содержать мнения и перспективы. Кружит вокруг предмета, подходя с разных сторон. Служит учёбе, как tutorial, но через понимание, а не действие.

## Компас

| информирует действие | применению навыков | How-to guide |
| информирует познание | применению навыков | Reference |
| информирует познание | приобретению навыков | Explanation |

## Маппинг на типологию wiki

Типология wiki (`concept/entity/source/project`) классифицирует страницы **по природе артефакта** — что это за объект. Diátaxis классифицирует **по назначению для читателя** — зачем ему это читать. Оси ортогональны, не конфликтуют.

| Diátaxis | Wiki-тип | Комментарий |
|---|---|---|
| Tutorial | — | Нет в wiki, не нужен пока |
| How-to | project/, entity с tag tech | ROADMAP, инструкции |
| Reference | entity, source | Фактология, спецификации |
| Explanation | concept | Контекст, почему, связи |

## Когда применять

1. **Пользовательская документация Kingthronoid (koid)**: когда появится — строго по Diátaxis (туториал для новых игроков, how-to для продвинутых, reference по механикам, explanation лора/дизайна)
2. **Написание wiki-страниц**: осознанно выбирать — эта страница справка (reference) или объяснение (explanation)? Не смешивать
3. **Диагностика проблем**: если документация «не работает» — проверить компасом, не смешаны ли виды

## Workflow Diátaxis

1. Рассмотри текущую документацию
2. Спроси: можно ли улучшить?
3. Реши одно улучшение, однако малое
4. Сделай его
5. Повторяй
