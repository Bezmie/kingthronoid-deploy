# How to Design Idle Games — Machinations

Статья Machinations.io по дизайну idle-игр. Фокус на архитектурных механиках.

## Key Points

### Core Loop + Meta Loop: Two-Level Architecture

**Core loop** — простой цикл: клик → ресурс → покупка → больше ресурса/клик. Имеет конечный срок вовлечённости сам по себе.

**Meta loop** — сложный слой поверх core loop, удерживающий игроков. Может включать:
- Развитие персонажей/билдов
- Билд-чейны и деревья прокачки
- Фарм редких наград
- Командные/синергетические механики
- Постепенное введение новых механик по мере прогресса

Архитектурный вывод: **нельзя полагаться на одну механику** — нужны множественные взаимодействующие механики в meta loop.

### Economy: Primary/Secondary Currency Model

| Валюта | Частота | Назначение | Источник |
|--------|---------|-----------|----------|
| Primary | Высокая | Базовые апгрейды (увеличение атаки, генерации валюты) | Авто-фарм, клики |
| Secondary | Низкая | Апгрейды beyond basic gear | Конец стадий, боссы |

- На secondary currency **всегда дефицит** → стимул к real-world покупкам
- Primary currency → покупка базовых апгрейдов → **увеличивает генерацию primary currency** (положительная обратная связь)
- **Баланс**: достаточно ресурсов для удержания + достаточный дефицит для монетизации

### Rewards and Balance

- Игрок должен чувствовать награду за **активное** и за **idle** время
- Мало наград → нет мотивации. Много → обесценивание ресурсов
- Return reward: крупная порция basic currency при возвращении в игру
- Achievement counter: видимый показатель генерации (ресурс/мин, ресурс/час)

### Idle Mode vs Active Mode

- **Idle mode**: робастный офлайн-прогресс, игрок всегда возвращается к награде
- **Active mode**: не должен сводиться к "зашёл-потратил-вышел", нужна вовлечённость
- Оптимизация перед idle mode = стратегический элемент
