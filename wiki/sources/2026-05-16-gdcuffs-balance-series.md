# Игровой баланс с нуля (цикл 7 статей, gdcuffs)

Цикл статей для начинающих: от подхода к балансу без формул до комплексной экономики и монетизации. Практический фреймворк, минимум академичности.

## Key Points

1. Баланс = геймдизайн, не математика. Правильные ответы в геймплее, не в формулах. Таблички упрощают работу, но не делают лучше.
2. Матмодель = гипотеза, требует доказательства в геймплее. Reverse engineering без опыта скорее навредит.
3. Workflow: константы (что важно) -> прогрессии -> эффективность -> экономика. Остальное выводится из констант.

## #1: Introduction and Preparation

- Баланс = любые числа, влияющие на геймплей
- Простые игры: числа с потолка, правка на глаз. Сложные: без табличек физически невозможно
- Подготовка: жанр/платформа определяют порядок чисел (тактика = маленькие, idle = огромные, action = визуально различимые)
- PvP: разрыв между уровнями не должен быть слишком большим. Прокачка: быстрый старт + равномерная подача контента

## #2: Constants and Progressions

- **Константы**: значения, заданные заранее. Остальное выводится из них. Выбор: что важно = константа (длительность боя), что неважно = выводится (отношение HP/DMG)
- **Формульные прогрессии**: `value = level^X * Y`. Не рекурсивные (Фибоначчи неудобен). Подгонка X и Y под крайние значения и скорость роста
- **Базовая прогрессия**: одна для важнейших значений. Производные через множитель или степень. Снижает путаницу при множестве связей
- **Круглые значения**: MROUND для часто отображаемых чисел. Столбец проверки после округления

## #3: Combat Effectiveness

- `PW = HP * DMG`. Все параметры сводятся к одному числу
- Крит: `DMG = DMG * (1 + CRIT%)`. Уворот: `HP = HP / (1 - DODGE%)`. Несколько эффектов: учитывать очередь срабатывания
- Лечение: коэффициент 0.7-0.8 к DMG (целитель не всегда эффективен)
- Условные бонусы (урон по типу врага): `эффект * доля таких врагов`
- Дальность: нет точного матрешения, зависит от тактики игры
- Группа: `PW(N) = HP*N * DMG*(1 + 0.7*(N-1))`. Коэффициент 0.7 = смертность
- Синергия: не балансировать превентивно. Проблема = доминирование 1-2 комбинаций, решать по аналитике
- **Рейтинги вместо %**: `Armor% = Armor / (Armor + Penetration)`. Никогда >100%. Пенетрация = прогрессия с множителем (1.5x для 40% против равного)

## #4: Models and Simple Economy

- Модель боя: не обязательна, но мотивирует. HP-DMG по ходам/секундам
- Модель экономики: контролирует контент, время, дефицит, дыры баланса. Не определяет, а контролирует
- Подготовка: чистое время, расчетное время, объем контента, примерные цены, жесткость экономики
- Минимальная экономика: стоимость всего / скорость заработка = время. Недостаточно для f2p
- Совмещенная модель: уровень -> доход -> расход -> баланс. 3 ключевых этапа: первые часы (подробно), переломные точки, крайние уровни

## #5: Complex Economy: Behavior and Cycle

- Модель по режимам: отдельная таблица на режим, значения передаются в основную
- "Если ты не знаешь, что делает игрок -- он тоже не знает"
- **Простой цикл**: активности завязаны / ограничены / единственная выгодная стратегия
- **Сложный цикл**: выбор строго мотивирован (если критерии неясны -- выбор не нужен)
- Ресурсы служат циклу, не наоборот. Вводить ресурсы когда требует баланс/цикл
- Расходы: привязка к прогрессу (уровень, рейтинг). Желание = открылась возможность + малый выбор
- Сливы: низкий приоритет, прогрессивная цена, практически неограниченные
- Гача: скрывает реальную стоимость, не пугает цифрами

## #6: Monetization and Economy

- 5 причин платить: сейчас / пройти дальше / преимущество / гештальт / выделиться
- Таймеры: цена минуты в премиум-валюте
- Дефицит: прогрессия расходов обгоняет доходы с определенного этапа. Держать разницу на уровне, не растить бесконечно
- После платежа: быстро выровнять сложность. Награда = ускоренный рост до нормы
- Конкуренция = замаскированный аукцион. Киты превращают игру в битву ставок
- Моделирование конкурентных механик: учитывать разброс активностей, формировать группы по уровню

## #7: Probability, Learning Curve, Conclusion

- Тервер реально почти не нужен. Моделируется усредненное поведение, не конкретные сценарии
- Монте-Карло выручает когда нужна вероятность
- Кривая обучения != кривая сложности. Контент на уровень + сложность освоения новых механик. Пики = перегруз, провалы = скука
