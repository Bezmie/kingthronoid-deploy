# Value Chains — A Method for Creating and Balancing Faucet-and-Drain Game Economies

**Автор**: Daniel Cook (Lostgarden), декабрь 2021
**URL**: https://lostgarden.com/2021/12/12/value-chains/

## Суть

Метод моделирования и балансировки игровых экономик как цепочек ценности (value chains), завершающихся психологическими якорями (anchors). Экономика типа «кран-и-слив» (faucet-and-drain) — генерация, трансформация, уничтожение ресурсов.

## Ключевые концепции

### Цепочка ценности (value chain)
Линейная последовательность узлов: действие → входы → выходы → следующий узел → ... → якорь (anchor). Каждый последующий узел «тянет» (pull) ресурсы из предыдущих. Обрыв цепочки = потеря смысла.

### Якорь (anchor)
Терминальный узел — реальная психологическая потребность (SDT: autonomy, competence, relatedness; Quantic Foundry: destruction, excitement, completion, power, fantasy, design, discovery...). Ценность всех предшествующих узлов производна от якоря.

### Эндогенность смыслов
Смысл в игре возникает из структуры, не привносится извне. Ценность элемента — не внутреннее свойство, а результат его позиции в ценностной сети.

### Экономика faucet-and-drain
- **Faucets (краны)**: ресурсы генерируются из ничего
- **Transforms**: однонаправленные преобразования
- **Drains (сливы)**: избыточные ресурсы уничтожаются

Свойства: постоянный спрос, ограниченные петли обратной связи, лёгкость объяснения и балансировки.

## Типы источников (Sources)

| Тип | Мощность | Формула | Ключевое свойство | Проблема |
|-----|----------|---------|-------------------|----------|
| **Capped** | x⁰ | Total = const | Фиксированное суммарное количество | Хрупкость при изменении длины игры |
| **Trickle** | x¹ | Total = rate × t | Фиксированная скорость поступления | Бесконечное накопление → избыточность |
| **Grind** | x¹ | Total ≈ rate_player × t | Неограничен игроком | Высокая вариативность (дефицит ↔ избыток) |
| **Investment** | x¹⁺ | Total ≈ a × e^(kt) | Положительная петля: ресурс → реинвестиция | Ранний дефицит, поздний экспоненциальный избыток |
| **Random** | шум | Среднее распределения | Лут-таблицы, кубики | Outlier-опыт; решение: constrained randomness, pity-системы |

**Вариации Investment**: добавить trickle-источник для устранения раннего дефицита (повышенный стартовый базис).

**Упрощение Random**: использовать среднее → сводится к capped/trickle/grind/investment.

## Типы стоков (Sinks)

| Тип | Мощность | Формула | Ключевое свойство |
|-----|----------|---------|-------------------|
| **Fixed** | x⁰ | Consumed = const | Однократное потребление |
| **Repeatable** | x¹ | Consumed = cost × n | Повторяемое потребление фиксированного количества |
| **Exponential** | x¹⁺ | Cost_n = base × multiplier^n | Каждый прирост стоит экспоненциально больше; всегда «место» для поглощения |
| **Competitive** | адаптивная | max(all players' inputs) | Кто вложил больше — получает приз; нет потолка |

## Правила балансировки

**Фундаментальный принцип**: источники низкой мощности → стоки равной или большей мощности.

### Игра фиксированной длины
- Capped → Fixed
- Trickle → Repeatable
- Investment (становится capped/trickle) → Fixed/Repeatable

### Ongoing-игра (idle/F2P)
- Capped → Fixed (только tutorial/events)
- Trickle → Repeatable / Exponential / Competitive
- **Grind/Investment → ТОЛЬКО Exponential / Competitive** (Fixed и Repeatable будут переполнены!)

**Принцип t→∞**: источник мощности xⁿ⁺¹ **всегда** переполнит сток мощности xⁿ при любой величине стока.

**Натяжение цепочек**: стоки должны быть чуть больше источников — не слишком (дефицит), не слишком мало (провисание). «Цепочка всегда слегка натянута».

## Архитектура множественных цепочек

### Параллельные
Каждая цепочка — уникальные ресурсы, без перекрытий. Плюсы: независимая балансировка, модульность. Минусы: bespoke-ресурсы, меньше эмерджентности.

### Баффы/Boost
Цепочка B производит бафф, усиливающий цепочку A. Якорь баффа — эффективность/power fantasy.

### Множественные дифференцированные входы
Monster A → Horns; Monster B → Gems; Level Up требует Horns AND Gems. Игрок обязан пройти оба, но выбирает порядок.

### Перелив (Overflow)
Когда fixed sink заполнен, избыток течёт в следующую цепочку. Обслуживает разные мотивации: прогрессоры → уровни, декораторы → крафт.

### Lock-and-Key Choices
Key resource (capped) → Lock nodes (больше, чем ключей). Opportunity cost: выбрав один lock, теряешь другие. Обеспечивает сильный pull и натянутую цепочку.

## Практика для idle-игр

1. **Investment source + чуть более мощный exponential sink** — базовый паттерн, но не вечен → **ascension/prestige** для хард-ресета
2. **Капирование investment**: хардкап уровней → превращение в trickle
3. **Никогда** не использовать exponential source без exponential sink
4. **Leveling** = exponential repeatable sink; при фиксированном числе уровней — краткосрочно exponential, долгосрочно fixed
5. **Content treadmill** (capped + fixed) → бесконечная потребность в контенте; лучше repeatable/exponential sinks
6. **Marginal value erosion**: повторение снижает ценность → burnout; leverage = игровое время / стоимость контента; типичный leverage босса Nintendo = 3
7. **Content recharging**: люди забывают — предмет через 2 месяца снова ценен
8. **Параллельные цепочки** = модульность для LiveOps (событие добавило цепочку → событие закончилось → цепочка удалена)
9. **Overflow** для нескольких аудиторий: одна цепочка ядра → разные направления траты → разные якоря

## Цикл подключения игрока

1. **Unmet needs** → play как seeking behavior
2. **Player promise** → игра обещает удовлетворить потребность (Diablo = власть, AC = расслабление)
3. **Onboarding** → ввод в ранние узлы; действует goodwill
4. **Understanding the path** → игрок требует показать путь к якорю; цепочка должна быть видимой
5. **Demonstrating need fulfillment** → как можно скорее показать реальное удовлетворение

## Экстринская vs интринская мотивация

- Спектр, не бинарность; одна механика — экстринская для одного, интринская для другого
- Рутина на службе высших потребностей **всё ещё** активирует чувство компетентности
- Якоря «числа вверх» не поддерживают интринскую мотивацию
- Red flags: «меня заставляют» → слишком экстрински; «сначала не понравилось, теперь нравится» → переход к интринской
